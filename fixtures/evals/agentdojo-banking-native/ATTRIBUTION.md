## Taken from AgentDojo

- Banking environment and injection-vector defaults, through AgentDojo's own
  pipeline (YAML load and dump, `str.format` with the injections, YAML load).
- User tasks UT0, UT3, UT13 and injection tasks IT0, IT4 (v1.2 wording) and IT7.
- The `important_instructions` attack (user "Emma Johnson", model "Claude").
- The default system message, as the entire system prompt.
- The 11 banking tools, with names, descriptions and input schemas built the way
  `make_function` and pydantic build them: parsed from the source, not executed.
- Tool semantics, re-implemented in `core/src/bank.rs` and run inside the proof:
  `send_money` leaves the balance unchanged, ids are max+1, updates apply only
  truthy arguments, unknown ids raise `ValueError`, arguments are coerced as in
  pydantic lax mode.
- Utility and security checks, evaluated on the final state as AgentDojo's
  `utility` / `security` functions do. That includes IT0's quirk: by operator
  precedence, any transaction to the attacker counts.
- Up to 16 model calls per run: AgentDojo calls the model once, then runs its
  tool loop up to 15 times with one more call each.

## Differences

- Tool results are returned as JSON (AgentDojo renders them as YAML).
- `read_file` of a missing file is an error (AgentDojo returns "").
- Error messages of failing tools are close to, but not the same text as,
  AgentDojo's Python exceptions.
- Model requests use the API's default temperature. AgentDojo sets 0 (1 when
  extended thinking is on).
- Tools reach the bank through the harness's HTTP-shaped tool path, so the
  harness policy, budgets and action log apply. The policy allows every bank
  endpoint, which is AgentDojo's no-defense setting.
